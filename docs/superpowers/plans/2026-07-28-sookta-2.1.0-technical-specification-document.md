# Sookta 2.1.0 Technical Specification Documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** สร้าง Technical Specification ของ Sookta Application 2.1.0 เป็น Markdown และ Word แยกจากเอกสารกลาง โดยลงรายละเอียดถึง architecture, route/state, data contract, algorithm, ML asset, persistence, export, platform และ test mapping

**Architecture:** ใช้ evidence inventory และ document builder ที่ผ่านการตรวจจากเอกสารกลาง แต่สร้างสารบัญ เนื้อหา แผนภาพ ตาราง และภาคผนวกของ Technical Specification ใหม่ทั้งหมด เอกสารต้องอ่านได้ด้วยตนเองและใช้ source file/class/method/test เป็นหน่วย traceability หลัก

**Tech Stack:** Markdown, bundled Python 3, shared `tooling/sookta_document_builder.py`, `python-docx`, Pillow, Sarabun, LibreOffice/`soffice`, Flutter source/tests, iOS plist, Android manifest/Gradle

## Global Constraints

- เริ่ม plan นี้หลังเอกสารกลางทั้ง Markdown และ DOCX ผ่าน completion gate แล้วเท่านั้น
- ชื่อ release/document version ต้องเป็น `Sookta Application 2.1.0`
- Document Control ต้องระบุ branch, commit SHA และ internal version/build จาก source snapshot
- ภาษาไทยเป็นหลัก ใช้ English สำหรับ identifiers, schema, formula และ standard names
- Word ต้องใช้ Sarabun สำหรับ Latin และ Complex Script
- Technical Specification เป็นเอกสารอิสระ ไม่บังคับให้เปิดเอกสารกลางประกอบ
- ส่งมอบเฉพาะ `.md` และ `.docx`; ไม่สร้าง PDF
- ไม่แก้ application source code, formula, threshold, model asset หรือ platform configuration
- ทุก algorithm claim ต้องมี source file/class/method mapping
- ทุก requirement ที่กล่าวถึงต้องมี test/UAT evidence หรือระบุว่าเป็น design/configuration evidence
- DOCX ใช้ A4 portrait, margin 2.54 ซม., preset `compact_reference_guide`, header pattern `memo_masthead` และ named override เป็น Sarabun
- ต้อง render DOCX เป็น PNG และตรวจทุกหน้าก่อนส่งมอบ
