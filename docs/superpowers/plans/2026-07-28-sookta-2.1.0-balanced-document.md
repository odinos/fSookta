# Sookta 2.1.0 Balanced Documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** สร้างเอกสารกลางแบบสมดุลของ Sookta Application 2.1.0 เป็น Markdown และ Word ที่อ่านได้ทั้งคณะวิจัยและทีมพัฒนา พร้อม Flow, Workflow, สูตรทั้งหมด, guideline mapping และหลักฐานตรวจสอบย้อนกลับ

**Architecture:** ใช้ Markdown เป็น source of truth ของเนื้อหา แล้วแปลงเป็น DOCX ด้วยเครื่องมือ Python ที่กำหนด style, numbering, table geometry และแผนภาพแบบ deterministic ตัวเอกสารอ้างอิง source code/model asset/test จริง และแยกมาตรฐานภายนอก การประยุกต์ของ Sookta และ coefficient ที่ยังเป็น research template อย่างชัดเจน

**Tech Stack:** Markdown, Mermaid source blocks, bundled Python 3, `python-docx`, Pillow, Sarabun, LibreOffice/`soffice`, Flutter tests, official web sources

## Global Constraints

- ชื่อ release/document version ต้องเป็น `Sookta Application 2.1.0`
- Document Control ต้องระบุ branch, commit SHA และ internal version/build จาก source snapshot แยกจาก release/document version
- ภาษาไทยเป็นหลัก ใช้ภาษาอังกฤษเฉพาะชื่อมาตรฐาน โมเดล สูตร ตัวแปร class/method และคีย์เวิร์ดที่จำเป็น
- Word ต้องใช้ Sarabun สำหรับ Latin และ Complex Script
- เอกสารกลางเป็นไฟล์อิสระ ไม่ต้องเปิด Technical Specification ประกอบ
- ส่งมอบเฉพาะ `.md` และ `.docx`; ไม่สร้าง PDF
- ไม่แก้ application source code, สูตร, threshold หรือ model asset
- ห้ามกล่าวอ้างว่าแอปได้รับการรับรอง ISO หรือใช้มาตรฐาน ISO ทั้งฉบับเมื่อ implementation เป็นสูตรประยุกต์
- แยก production path, app-specific calibration, research template และ deprecated component
- ใช้ APA 7 และ primary/official source ก่อนแหล่งสรุป
- DOCX ใช้ A4 portrait, margin 2.54 ซม., preset `standard_business_brief`, header pattern `editorial_cover` และ named override เป็น Sarabun
- ต้อง render DOCX เป็น PNG และตรวจทุกหน้าก่อนส่งมอบ
